Federated Database System

Healthcare data integration

A federated database gives one query interface to several independent databases while the data stays in the original systems. In this project, hospital records in Microsoft SQL Server and insurance policies and claims in Neo4j are combined through a FastAPI layer, so one API call returns a full patient profile without copying or syncing data.

Each system keeps its own schema and ownership. A schema mapping layer handles the differences between the relational and graph models, there's a React interface with separate portals, and everything runs in Docker Compose.

Python, FastAPI, SQL Server, Neo4j, React, Pydantic, Docker

Real-Time IoT Data Pipeline

Industrial sensor monitoring

An end-to-end pipeline that monitors 25 sensors across 5 industrial locations, tracking temperature, humidity, CO2, pressure, and light. It handles over 45,000 messages an hour with under 50 ms average latency, validates and normalizes the data, raises threshold alerts, and flags anomalies with z-scores.

Kafka carries the stream, PostgreSQL stores the time series, Airflow runs the hourly batch jobs, and Prometheus and Grafana power the dashboards.

Apache Kafka, PostgreSQL, Apache Airflow, Prometheus, Grafana, Docker

Explainable AI for Hospital Discharge Data

Healthcare analytics

I clustered NY SPARCS inpatient discharge records with K-means and DBSCAN, then profiled each cluster by length of stay, cost, severity, and demographics. Feature importance, radar charts, heatmaps, and PCA plots show what defines each group.

The results point to a small number of patient clusters that account for a large share of costs, which is useful for resource planning. Healthcare decisions often rely on black-box models, and this project shows how explainability can make the insights easier to trust and act on.

Python, scikit-learn, K-means, DBSCAN, PCA
